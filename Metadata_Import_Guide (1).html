The idea: a workbook of instructions

The Risk Engine needs well over a hundred inputs: correlation matrices, shock parameters, mapping tables, cash flows, technical provisions, regulatory templates. Instead of writing a separate program for each file, it uses metadata workbooks: Excel files that list every import and describe it.

Think of a metadata workbook as an instruction book. For each table, one line answers four questions:

QuestionAnswered by
What table do we need?The table name, for example PRM_EQUITY_SHOCK
How is it read?From an Excel worksheet, or by a program that extracts it
Where is the source?A file location with blanks that the run fills in (date, context, configuration)
Where does the result go?An output area, for example parameters or data quality references

Next to that list, each table has its own sheet describing the columns it should have: its schema. The schema is the template the imported data is fitted into.

In one line: adding or changing an import means editing the workbook, not the code.

The four steps of an import

1

Read the instructions

The process opens the metadata workbook and reads the control sheet, List_Of_Tables: one line per import.

2

Find the source

It fills the blanks in each file location with the values chosen in the form at the start of the run, such as the reporting date and configuration, then opens the named worksheet or calls the named program.

3

Fit the data to the template

It uses the table's schema sheet to keep the expected columns, rename them where asked and give each the right type: text, date or number.

4

Save the result

It saves the finished table in the output area named on the line, ready for the later stages of the Risk Engine.

The key rule: only the worksheet named on a line is read. Another worksheet in the same file is ignored until someone adds a line and a schema sheet for it. Two lines never merge into one table.

Adding a new file, in three steps

1

Add a line to the control sheet

Give the table a clear, unique name, choose its output area and say which worksheet (or program) to read.

2

Add its schema sheet

Create a sheet named exactly like the table and list the columns it should have, with their types.

3

Run it

Put the file in its folder and start the run with the usual parameters. The new table is created with the others.

Glossary

Metadata
Information that describes other data, here the instructions for each import.
Metadata workbook
The Excel file holding the control sheet and one schema sheet per table.
Control sheet
The List_Of_Tables sheet: one line per import.
Schema
The template of a table: its column names, their order and their types.
Run parameters
The values chosen in the form at the start of a run, plus values derived from them, such as the period folder.
Placeholder
A name in braces in a file location, such as {thisrun_context_id}, replaced by the run's value.
Output area (library)
The labelled place a table is saved to, such as REF_PRM or CTX_SOU.
Function-based import
An import where a program extracts the data, instead of reading an Excel worksheet.
QRT
Quantitative Reporting Template: the standard Solvency II reports an insurer files with the regulator.
Cell range
A block of cells such as A10:F13, used to read one table out of a QRT template.
Parquet
The file format the tables are saved in, built for fast data processing.
Null
No value at all, which is different from zero or an empty text.
Overwrite
Saving a table replaces the previous one of the same name.

How import_structured_xlsx reads the sheet

  • Reads the worksheet with the Excel connector; if that fails, copies the file to /tmp and reads it with pandas, finding the sheet name case-insensitively.
  • Removes rows where every value is empty.
  • Matches columns by name: columns in both file and schema are kept and cast to their type; schema columns missing from the file become null.
  • Upper-cases all column names.

What a configuration import run does

1

Read the control sheet

Reads List_Of_Tables with the Excel connector in the ref layer, from a metadata folder built from the environment and reporting date.

2

Keep the Excel rows

Filters on IMPORT_FILE_IMPORT_METHOD = EXCEL, collects the rows and processes them one at a time (sequential, not parallel).

3

Resolve the source

Fills the placeholders in TABLE_SOURCE_PATH from run_parameters and takes the worksheet from IMPORT_FILE_EXCEL_SHEET.

4

Import and structure

Calls import_structured_xlsx with the metadata workbook location, target name, source file and worksheet.

5

Route to the output folder

Maps TABLE_LIBRARY to a folder and appends TABLE_NAME.parquet.

6

Save with overwrite

Writes Parquet in overwrite mode. A Spark Parquet destination is a folder of data files, even though its name ends in .parquet.

7

Report and continue

Prints timings and a row count, then moves to the next row. At the end it prints the total loop time.

Adding a file

  • Add a row to List_Of_Tables with a unique TABLE_NAME and its TABLE_LIBRARY
  • Set IMPORT_FILE_IMPORT_METHOD and the worksheet (IMPORT_FILE_EXCEL_SHEET) or the function
  • Write TABLE_SOURCE_PATH with run-parameter placeholders in braces
  • Add a schema sheet named exactly like the table, with Column_Name and Column_Type
